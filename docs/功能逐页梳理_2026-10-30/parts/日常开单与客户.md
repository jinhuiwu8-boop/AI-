# 日常开单与客户：逐页功能梳理

依据：22张旧手机截图及规划v0.1-r2。截图只证明当时的界面表现，测试客户、占位金额、空状态均不证明功能完成。本文件仅供逐项人工修改，不融合旧代码。功能ID用于后续需求和验收追踪；“建议”尚未确认为需求。

## P01 工作台

![工作台原图](../../assets/手机界面原图/01_工作台_完整页面.jpg)

**截图现状：**顶部有开启提醒、试听及前台有效说明；日期旁有刷新。正文依次为图片开单、今日确认销售、待人工确认、未核销货物、打印需处理、本月销售、查客户及最近确认订单；底部为工作台/订单/我的。截图统计为测试状态。

**已确认处理方向：**保留入口和绿色风格，待核订单置顶；图片开单必须保留，电子单最终确认保存计销。首期交付APK锁屏提醒，不能把图中前台语音视为完成。代搭赠核销属后续，趋势图后做。

| 功能ID | 内容 | 处理 |
| --- | --- | --- |
| P01-F01 | 提醒、试听、刷新 | 前台提醒可保留；补原生通知 |
| P01-F02 | 图片开单、待人工确认 | 主入口保留 |
| P01-F03 | 今日/月销售、最近订单 | 只读已确认销售，不因补打增长 |
| P01-F04 | 未核销、打印需处理、查客户 | 核销后续；其余保留 |
| P01-F05 | 三项底部导航 | 保留 |

**用户步骤：**
1. 登录进入工作台，检查待核数量与设备异常。
2. 点击待人工确认处理微信订单；或点图片开单自主开电子单。
3. 点击打印异常进入任务；查客户进入客户档案。
4. 查看最近订单，必要时刷新；授权通知后试听。

**系统处理/状态与异常：**分别显示加载、空列表、刷新失败；刷新不创建订单。待核通知引用真实订单；云或Jetson离线应显示状态，数据未加载不能当成0。

**待确认建议：**建议将销售卡缩小，为待核与打印异常腾出首屏；建议隐藏首期无用的未核销卡。

**已确认处理方向：**保留销售查询，补客户、日期、状态搜索；电子单人工确认保存即计销，纸质单在确认开单时计销，打印与补打不再次计销。趋势图后续增强，先保证订单与金额口径一致。

| 功能ID | 内容 | 处理 |

| P02-F01 | 日/月/年销售与单数 | 保留，来源为有效销售事件 |
| P02-F02 | 近30天趋势 | 后续增强 |
| P02-F03 | 已确认订单、刷新 | 保留，增加详情入口 |

**用户步骤：**
1. 从底部订单进入，查看统计和列表。

**系统处理/状态与异常：**按统一货款统计口径汇总，抵扣、抹零、应收分别展示。空结果与接口失败分开；出纸状态独立于订单确认状态，打印失败不撤销销售。

**待确认建议：**建议列表显示客户、确认时间、销售额/应收和打印状态；作废的统计冲回与已确认订单更正操作建议另定详细规则。

## P03 待人工确认

![待人工确认原图](../../assets/手机界面原图/03_待人工确认_完整页面.jpg)

**截图现状：**只有返回工作台、大块“暂无待确认内容”、刷新与底部导航，未展示有订单时的列表、原消息、候选客户或确认按钮。不能从空页推断核对流程已实现。

**已确认处理方向：**这是微信主流程的核心入口，必须补完整待核列表与详情。客户名开头，后续产品消息连续60秒无新信息封单；封单只送识别/核对，不自动确认或打印。图片与语音首期支持；Jetson返回候选，最终由人核对。

| 功能ID | 内容 | 处理 |
| --- | --- | --- |
| P03-F01 | 返回、刷新、空状态 | 保留，区分加载失败 |
| P03-F02 | 待核列表、任务状态 | 新增来源、时间、客户及异常 |
| P03-F03 | 原文/原图/语音与识别候选 | 新增对照及播放 |
| P03-F04 | 客户、SKU、数量、单位、价格 | 逐项人工核对与修改 |
| P03-F05 | 确认、草稿、待归属消息 | 补齐，按版本保护 |

**用户步骤：**
1. 收到APK提醒后打开待确认，查看订单是否仍需处理。
2. 选择订单，先看转发人、消息批次及客户原始叫法，核实实际客户；转发人不能代替客户。
3. 对照原文字、图片和语音，选择正确SKU/规格，检查数量、单位及拆箱瓶数。
4. 核对价格来源：最近确认价为默认，较新的客户资料人工调价生效。缺价时人工填写；本页改价确认后供该客户下次使用，无“仅本单”。
5. 核对回收抵扣、抹零原因、备注与最终应收，预览单据；单瓶除价及最终应收均按规则到角。
6. 明确确认纸质开单后冻结并一次计销，创建打印任务；尚未确认可继续编辑。出纸由人查看，未出纸在订单页重打。

**系统处理/状态与异常：**显示排队、识别中、待核、识别失败；无客户开头或封单后迟到消息进入待归属/续单确认。重复消息不重置计时，迟到模型结果不覆盖人工编辑。并发修改、价版本变化时要求刷新或明确修改，重复确认防重。已确认纠错自动进入训练流程，训练不写全体价格表。

**待确认建议：**建议列表优先显示缺客户、缺价及单位歧义；建议核对详情复用P19/P22的表单结构，避免重复维护两套规则。建议明确待归属消息合并的入口及权限。

**人工修改：**审核状态：____；意见：____；确认人/日期：____。

## P04 图片开单：输入页面

![图片开单输入原图](../../assets/手机界面原图/04_图片开单_完整输入页面.jpg)

**截图现状：**顶部提醒、返回与“本机测试”；内容框示例“5件470一麦退5个空箱”，按住说话、识别并填写、填入示例、填写商品明细、客户名和未保存预览。名为图片开单，但本图未见拍照/选图入口。

**已确认处理方向：**与P19、P22合并为一个开单流程；首期补拍照/选图、语音录制识别。工作台自主开电子单，人工最终确认保存后计销；预览不计销，随后可保存相册或打印同单。

| 功能ID | 内容 | 处理 |
| --- | --- | --- |
| P04-F01 | 内容输入、按住说话 | 保留，补权限及失败状态 |
| P04-F02 | 识别并填写、商品明细 | 保留，识别结果须核对 |
| P04-F03 | 客户名称、预览 | 改为关联主档及来源清晰 |
| P04-F04 | 示例、本机测试、图片入口 | 示例仅调试；新增图片输入 |

**用户步骤：**
1. 工作台进入图片开单，输入文字或拍照/选图、录制语音。
2. 点击识别并填写，检查识别原文与候选结果。
3. 选定真实客户；进入商品明细逐项核对。
4. 检查电子预览后按P19/P22完成最终确认。

**系统处理/状态与异常：**识别失败可改输入或手填，不伪造价格。编辑输入应使旧核对标志失效；权限拒绝、录音取消、图片上传失败分别提示，不生成空单。

**待确认建议：**建议正式版移除“填入示例”和“本机测试”；建议允许一张订单附多张图，数量上限另定。

## P19 图片开单：完整商品明细与备注

![商品明细原图](../../assets/手机界面原图/19_图片开单_完整商品明细表单_含备注.jpg)

**截图现状：**包含输入/语音区、客户、未保存预览、可增删的商品卡（名称、规格、数量、单位、单价、行金额）、空瓶/空箱抵扣、可展开的手动抹零/原因/备注，底部货款、抵扣、应收、核对勾选与保存按钮。客户及商品为空时显示待核，按钮不可用。

**已确认处理方向：**作为统一核对表单，不另建重复页面。客户与商品必须关联主档；本页改单价并确认后影响该客户以后开单，无“仅本单”。单瓶由有效箱价除瓶数后四舍五入到0.1元，再乘数量；最终应收同样到角。电子确认保存一次计销，纯电子不自动打印。

| 功能ID | 内容 | 处理 |
| --- | --- | --- |
| P19-F01 | 客户及商品名称/规格 | 改为稳定ID选择与候选核对 |
| P19-F02 | 增删商品、数量、单位、单价 | 保留，展示价源与单位换算 |
| P19-F03 | 回收抵扣增删 | 保留，完整个数、独立抵扣价 |
| P19-F04 | 抹零金额/原因、备注 | 保留，默认不抹零 |
| P19-F05 | 合计、核对勾选、确认保存 | 保留，确认后冻结并防重计销 |

**用户步骤：**
1. 先核实实际客户；对照输入原文/图片/语音选中正确客户。
2. 逐行选择商品SKU及规格，填写数量与销售单位；增加遗漏商品、删除误识别行。
3. 查看单价来源，核实最新客户价。缺价人工补，手改价确认后成为该客户该单位的新价；检查拆箱瓶数和到角结果。
4. 有空箱/空瓶回收时添加回收项目及完整数量，核对抵扣价和金额，不能用商品销售价推算。
5. 需要手动抹零时填写减免金额与原因，填写备注；核对货款、抵扣、抹零及舍入差额后的应收。
6. 检查预览，确认客户、商品、价格与抵扣，勾选核对后点击确认保存。电子模式只有正式电子图片持久保存成功后才一次计销；成功后进入同一订单，按需保存相册或打印。

**系统处理/状态与异常：**客户/SKU/单位不明、缺价、非法数量或抵扣超可抵货款时阻止确认。改动核对字段后旧勾选失效，旧识别结果不得覆盖手改。提交时检查草稿和价格版本；重复提交只确认一次，失败显示原因并保留草稿。历史单据不随后续调价变化；已确认纠错自动训练但不能写全体客户价。

3. 勾选已核对，点击确认保存；只有正式电子图片持久保存成功并完成本次确认才计销，等待明确成功回执，不能把预览已显示当成保存成功。

6. 未出纸在订单页重新打印，查看旧任务是否仍处理，确认后建立新的打印尝试；重复点击同次重打不多创建。
