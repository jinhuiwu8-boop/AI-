# A03 客户关联退货页面回交

2026-11-03。依据用户最新要求及本批次 `01_接口差量.md` 实施，替代新退货必须手选原销售单的页面流程；旧退货数据仍按冻结单据展示。

## 已实现

- `web/app.mjs`：退货统一入口只预选客户，客户、商品、箱/瓶、数量组成退货草稿；调用 `GET /api/return-prices`，历史单价只读。缺价、歧义、未完成报价、包装未确认均在提交前阻止。更换客户、商品、单位立即清报价、包装确认及总核对。
- 沿用请求代次防竞态、统一金额估算、提交未知结果保留和幂等重试；报价身份加业务类型，`RETURN_PRICE_VERSION_CONFLICT` 重读历史报价并取消核对。相同报价版本重复读取保留逐行包装确认，版本变化取消确认。
- 新提交传 `returnBasis: CUSTOMER_HISTORY`、`checked`、`customerId` 及逐行 `returnPriceVersion`、必要包装确认；不传顶层原销售单，不由页面写取价证据，也不在浏览器重算箱价拆瓶。
- 销售详情“为该客户开退货单”只预选客户；新退货详情展示行级历史价来源，旧记录继续显示原单/原版本。候选、更正流程保持独立。
- `web/mobile-app.mjs`：退货沿用紧凑明细和最终核对区图片预览；仅销售保留未接入的文字/语音草稿入口。未新增原生、模型、打印成功声明。
- `web/mobile.css`：仅增加包装确认行的间距、颜色及勾选对齐。

## 自查与交接

`node --check web/app.mjs`、`node --check web/mobile-app.mjs` 通过；静态搜索确认没有新退货原销售单选择器、旧草稿数量映射或顶层来源提交。金额仍由既有统一估算作核对、服务端重算确认。

本口未操作浏览器、未修改共享后端和工程台账。客户累计购货量政策的保存放行由 ROOT 后端控制，页面不宣称无限退货或可退余额。ROOT 继续做接口集成、保存边界和真实页面验证；A07 独立验收。
