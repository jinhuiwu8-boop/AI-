## 已验证的边界

- 仅维护客户价、仅瓶销售及零价销售不冒充历史箱价；客户隔离，改走客户或归零后的旧快照不能重新成为有效价源。
- 数量更正不把旧价格提升到最新；非零实际改价更正成为最新历史价源。
- 100 元 / 24 瓶按 4.2 元逐瓶计价，24 瓶为 100.8 元；有历史依据而派生为 0 元的价格可区别于缺价，不更改以后常规售价。
- 销售行冻结包装不受当前商品包装变化影响；旧单缺包装显式回退当前主档，要求确认，主档变化使报价版本改变。最新多价或不同包装返回歧义，阻止回退旧价保存。
- 默认数量政策未配置时，新客户退货返回 `409 RETURN_QUANTITY_POLICY_UNCONFIRMED`，没有订单、事件、幂等记录或新图片保存副作用；旧原单退货继续通过。
- 服务端重算并冻结历史取价证据，忽略前端伪造 `priceSource`；篡改单价、过期版本、未确认旧包装均拒绝且无业务写入。
- 同一请求重试只形成一笔退货、一条 RETURN 事件；不同请求内容复用 ID 被拒绝。图片保存失败回滚业务状态，原请求可安全重试。
- 直接执行当前 `web/app.mjs` 内实际报价控制器的延迟响应测试：旧客户响应不能覆盖新客户价；同版本刷新保留包装确认，新版本取消包装确认。此项不冒充浏览器视觉验收。
- HTTP 历史价入口需会话，写入口需 CSRF；真实保存的 SALE 才产生可取历史价。默认新退货拒绝与旧原单接口兼容均通过实际请求验证。
- 未开放提示补丁：实际 HTTP bootstrap 明确返回 `customerHistoryReturn.canSave:false` 及产品提示“退货数量规则尚未确认，当前可核对预览，暂不能保存。”。实际 UI 控制器测试验证 RETURN 显示原因、禁用保存按钮，绕过按钮直接调用提交也不会发出写入；销售按钮不被此开关误禁用。历史报价及预览流程继续可用。

新退货保存核心的隔离测试显式注入了 **TEST ONLY 数量校验回调**，只验证报价、金额、事务及幂等边界；该回调不是正式无限退货政策，也未提供给实际 HTTP 应用。它不能用于宣称用户已确认数量上限。

## 只读页面检查

新退货界面选择客户、商品、箱/瓶和数量，没有强制原销售单选择器；历史单价只读。更换客户、商品或单位清掉旧报价与包装确认；缺价、歧义、报价加载/错误和未核对包装在提交前阻止。提交不携带顶层原销售单，普通销售、更正与候选识别流程仍分开。最终核对区继续展示退货草稿图片。
