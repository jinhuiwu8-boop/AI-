# 客户退货接口差量

2026-11-03。用户明确取消新退货单必须选择原销售单，改为选客户并沿客户历史开单价，散瓶按历史箱价除瓶数四舍五入到角。旧退货和原单命令保持兼容；新单不写顶层sourceOrderId，不改常规售价。

`GET /api/return-prices?customerId=&skuId=&unit=` 返回与普通取价相似的 `priceCents/version`，另有 `source`（HISTORY_CASE / HISTORY_CASE_DERIVED / MISSING / AMBIGUOUS）、sourceOrderId/sourceRevision/sourceLineId、priceConfirmedAt、casePriceCents、bottlesPerCase、packagingSource、productVersion、requiresPackagingConfirmation。

价格来自已确认SALE事件及冻结版本：非零实际改价更正参与，数量-only更正不把旧价抬为最新；排除退货、零价、仅维护而未成交的客户调价。瓶单位仅按历史箱价拆算，没有箱历史不能凭空用当前价或猜零。同一最新成交存在多价时阻止并提示歧义。新销售冻结包装，旧单无包装时明确取当前商品资料并要求逐行人工核对；版本必须含该包装变化。

新 `POST /api/returns`：`{operationId,returnBasis:'CUSTOMER_HISTORY',checked:true,customerId,items:[{skuId,unit,quantity,priceCents,returnPriceVersion,packagingConfirmed?}],note?}`。服务端事务内重算报价/核版本、核包装确认并生成PNG及唯一RETURN事件；前端不能写priceSource或任意改退货价。历史引用冻结在每行priceSource，只作取价证据，不冒充原单关联。100元/24瓶按4.2元逐瓶计价，24瓶为100.8元，不另作未授权封顶。

客户累计购货量是否作为防超退上限，已交Q00问题 Q-RETURN-CUSTOMER-LIMIT-01；未答复前不启用依赖该选择的新退货保存。历史报价、页面和兼容核查可先做。

本地正式HTTP应用的bootstrap明确返回`customerHistoryReturn:{canSave:false,unavailableReason:'退货数量规则尚未确认，当前可核对预览，暂不能保存。'}`。页面据此提示、禁用新退货保存并在提交前阻止；服务端仍以`RETURN_QUANTITY_POLICY_UNCONFIRMED`作最终拒绝，无业务/图片/幂等副作用。服务构造器内部数量回调当前仅供隔离测试，未在HTTP提供配置入口；不能把测试回调视为正式无限退货政策。答案确定后须同时实现真实策略、更新bootstrap状态并补对应联动验收，不能只改页面开关。
