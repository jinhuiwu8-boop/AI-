## 2. 提交前持久日志与恢复状态提案

状态名仅为语义，ROOT定稿；A06 owns边缘持久日志，A01 owns云任务租约/回执，A02 owns业务确认及销售。

| 阶段 | 必须持久记录 | 崩溃后处理 |
| --- | --- | --- |
| RECEIVED/PREPARED | 云任务与尝试ID、设备ID、订单/冻结版本、文档ID/字节摘要、校准/模板版本、份数1、租约相关身份 | 校验本地文件真实摘要；不能用过期租约自行打印 |
| SUBMIT_INTENT | 提交意图、唯一尝试键、时间、队列、文档身份，持久成功后才执行打印调用 | 意图后但无确切回执属于潜在已提交，先查队列/人工核对，不自动再次lp |
| ACCEPTED/UNCERTAIN/FAILED_BEFORE_SPOOL | 完整规范结果、队列ID（有则）、错误及提交证据 | 队列ID辅助对账，不证明实际出纸；不能把未知恢复成未提交 |
| OUTBOX_PENDING | 结果ID、内容摘要、回传次数/状态；原证据保留 | 重发同一结果，不重放打印调用；同结果幂等接受，异结果不能覆盖旧证据 |
| CLOUD_ACKED | 云明确已落库回执与结果身份 | 之后按审定保留策略清理媒体；日志/未知/未确认回执不能按临时目录策略丢弃 |
| HUMAN_REVIEWED | 人工出纸/未出纸结论、操作者、时间、原因，关联具体尝试 | 云端鉴权并防重；更新打印事实，不新增销售 |

持久化需要原子写/事务与落盘保证，不能只写内存或stdout。队列查询结果可能被清理；查不到旧编号不能证明没打印。驱动能返回缺纸/卡纸时记录具体来源/时间，不能把设备健康提示当该尝试出纸结论。

## 3. 新旧单据版本与重打合同

建议每个打印尝试不可变绑定：业务记录ID、单据类型、内容版本ID/摘要、文档ID/字节摘要、模板/校准版本、attemptID、首打/重打、所重打尝试引用、份数1、创建人/时间/原因。云/边缘/对象三处引用须一致，下载和提交前校验，不按当前客户价重新渲染历史内容。

更正按07保留原版和修正版，A02发更正/冲回事件，A06仅生成修正版单据。旧尝试继续指原版，旧PDF/回执不改写；更正后的默认打印指明确修正版。旧版本已有排队/提交任务时必须显示版本差异，避免旧单与修正单同时无提示出纸；如何撤销尚未提交任务由ROOT合同确定，不能声称可撤销已提交打印机的任务。

重打不是新订单或更正；每次固定一份，但累计次数未限制为一次。幂等应区分“同一次重打重复点击”与“人工明确新建下一次重打”。前者只创建一个attempt，后者保留新attempt及原引用；未知任务先现场核清风险，不因租约超时自动重打。人工出纸结论与业务销售状态分别展示。

## 4. 电子销售、退货图片与计销隔离

P22电子确认仅在正式图片持久保存和确认成功后计销；独立打印按钮消费已确认冻结单，不创建第二笔销售。纸质主路线确认计销并可靠创建首打任务，实际验纸独立记录。A06返回文档身份/摘要/持久读回证据，不直接写销售。

07允许图片入口“销售/退货”且仅老板处理退货；Q00最新回传确认选择原销售单、沿用原成交价，并可退部分商品。建议将documentType/业务类型、原销售单及原销售行引用作为冻结规范内容的一部分，预览、正式图片、订单列表均显式显示。退货保持正数量表达独立关联业务，不让渲染器把其普通items映射成一笔正向销售；也不可把空瓶/空箱returnCredit误当商品退货。退货价格采用关联原单成交价，不查询当前售价替换；部分退货逐行关联原商品及本次退货数量，由A02校验累计可退范围并输出冻结结果。相册重存/重试图片生成/云保存回执重放均不重复发生业务事件。A02定义退货统计和冲回，A06只忠实投影其已批准快照，不实现现金退款或库存会计。本次确认仅覆盖退货图片，不扩为纸质退货功能。
