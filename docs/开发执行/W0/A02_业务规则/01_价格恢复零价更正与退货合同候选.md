# W0-A02 价格、恢复、零价、更正与退货合同候选

日期2026-10-31；版本candidate-01；状态：待ROOT审阅冻结，非合同通过、非业务实现。依据根AGENTS、项目管理01/02、功能逐页01/03/04/05/06及最新`07_调价更正退货与启动确认_v0.2-r3.md`。07覆盖旧“未决定”文案；本次不修改旧稿、共享合同、schema或台账，不融合旧代码、不推送。

## 1 已确认与候选分层

**已确认业务：**客户/SKU/单位分别取最新有效价格事件；客户资料人工调价保存生效，核对手改确认影响以后，无“仅本单”；按钮±1元且保存才生效；恢复最近一次已保存调价前有效价并生成新事件。零价需人工明确，仅本次零价例外不改变以后常规价格。单瓶及最终应收到角。老板更正保留前后版本，先冲回旧销售再记正确销售。同一次更正防重；补打不计销。图片开单分销售/退货，退货正数量并明确类型，只有老板可更正/退货；退货不扩现金退款/库存。

**下述全部技术名称、字段、错误标识、状态和事务组织是候选设计。** 不是已实现API或数据库表；由ROOT统一合同后才能施工。Q-RETURN-01本轮已获用户答复（ROOT转达）：选择原销售单、沿用原成交价，可退部分商品；以下据此更新，不再列为待答。

## 2 通用命令与查询约束

输入公共信封建议：operationId（幂等键）、operationType、actor/device授权代次、targetId、expectedVersion、payload；云端从身份服务取得老板身份，不能信任客户端自报isBoss。金额用整分整数或等价十进制定点，单位/数量及包装版本明确；不得用浮点格式化替代到角。

输出建议：operationId、状态、目标业务ID、新版本、受影响事件ID、金额分项、来源和可重试说明。失败应说明是身份、主档、版本、金额、归属还是依赖待答；不能全部退成“识别失败”。

同operationId且同规范化输入重传返回原结果；同键异输入拒绝。不依赖客户端连续点击节流实现幂等；不同键并发仍用目标版本和唯一业务关联约束避免双计销。成功响应丢失按operationId查询结果，不重建业务。

## 3 价格读取、保存及恢复

**价格读取输入**：customerId、skuId、pricingUnit、包装版本；**输出**：effectivePrice、priceVersion、来源事件/确认单、时间、直接价或箱价派生及源版本、缺价状态。不得跨客户、跨规格、跨单位借价。

**保存输入**：该价格键、expectedPriceVersion、编辑后金额、修改来源。±1元只改变编辑态，用户可直接输入；保存成功追加人工价事件并更新有效版本。负价拒绝；0元常规价保存不能借本合同自动开放（已确认0价指明确开单，见下一节）。草稿不写有效价。

**恢复预览输入**：价格键和当前版本；输出最近一次已保存调价的前有效价、事件及当前版本。例100→保存110，恢复目标100，不是最初建档价。无前有效价则不可恢复并说明；不猜一个0价。

**恢复提交输入**：operationId、价格键、预览绑定当前版本/目标事件。云重新核验版本及目标后追加RESTORE类事件，恢复100立即用于后续，原110事件和历史订单仍在。预览后有新保存则版本冲突，重新展示目标，不静默恢复过期值。连续点击同一恢复防重；恢复事件之后再次点击的目标展示规则由ROOT冻结实现细节，不凭“恢复”二字暗定反复切换价。

箱价100/24瓶派生瓶价4.2元、3瓶12.60元；恢复源箱价后派生瓶价重算。明确人工瓶价与源箱价后续冲突的精确优先口径仍沿现有未决项，不能自行覆盖人工瓶价。

## 4 核对确认与零价例外

输入：orderDraftId、expectedDraftVersion、每行稳定SKU/单位、数量、单价及价版本、人工改价标志、零价明确标志、抵扣/抹零/原因、确认路线。云检查主档/授权/价版本，关键编辑使原核对失效。

非零人工手改价确认后追加该客户该SKU单位价格事件；只用默认价确认不应反向覆盖期间新调价。零价行必须人工明确且单据标识；即使该单“最近已确认”，其0价行也不能成为后续常规取价来源，不产生覆盖常规价事件。缺价null不得转成0；0价不是退货。训练可接非价格纠错标签，不能用零价样本改全体客户价。

电子路线：A02校验并形成待冻结版本→A06生成受控正式图片并持久读回→A02对准确版本一次完成确认、销售事件及相应非零价事件。对象外部存储与数据库用可恢复状态衔接；中途失败保持未完成，不先计销。纸路线：确认、唯一销售及首打任务/可靠outbox同一事务边界，出纸后不再计销。渲染/图库/重打均不写销售。

## 5 老板更正与冲回

输入：原orderId、expectedActiveVersion、operationId、原因、完整正确内容、必要价源确认。原销售有效版本必须仍是预期版本；先前版本/打印引用不覆盖。

输出：correctionId、oldVersionId、新versionId、冲回事件和正确销售事件、修订单据状态、净额。候选使用同一订单修订链而非无关联新订单；ROOT可调整物理实现，但前后关联不可丢。

事务：云验证老板及当前设备→校验原销售/更正目标→计算正确快照→在一次业务提交中记录更正关系、冲回原有效销售、记正确销售、推进有效版本。电子修正仍需准确新正式图片成功再完成；纸质更正的打印触发细节由ROOT冻结，不擅自自动多打。冲回和新计销不能只成功一半。重复请求不追加第二对事件；第二次合法更正应针对当前有效修订，不重复冲最初版本。

例原100，更正90：已有+100，新增-100及+90，净90。新版本纸打引用90版本，原100打印历史保留；补打90仅加打印尝试。更正中单价变更是否另推后续客户价，尚无专门明确口径，回ROOT/Q00，不能借更正无声改客户常规价。

客户更正示例：1箱×100误记C-A，实际应为C-B；C-A冲回100、C-B记100，全店净额仍100，不复制成两单各计100。数量更正示例：原2箱×100=200，正确1箱×100=100，追加-200/+100，全店净100；原2箱快照保留。

## 6 原单关联与部分退货

已确认输入：图片开单选择RETURN类型，老板、原销售单ID、原行ID及冻结版本引用、正退货数量、明确退货标识；客户/SKU/成交单位和单价由所选原行快照带出。可选部分商品及部分数量。输出独立关联退货记录，预览/正式图/列表显示退货，不能当第二笔正向销售。普通SALE数量仍不能任意负数。

价格沿用所选原行实际成交单价及计价单位快照，不用当前客户价，不因后续调价变化。原行0价退货仍0价，不能抬为现售价；退货不生成常规客户价事件。累计已确认退货量不得超过该原行可退销售数量；未经明确单位换算不可混用箱/瓶累计。统计日期、抵扣/抹零反向分配尚需技术方案细化，不擅造已确认财务规则。

候选提交事务：验证老板/原单原行及版本归属→按原行快照计算→原子检查累计已确认退货量及并发版本→确认退货和反向销售事件、更新累计数量并记录幂等结果。两次并发退货必须锁定/条件更新同一可退额度；不能分别读取旧余额后都通过。电子退货正式图持久成功后才完成相应确认；重复请求不扣第二次额度、不再减销售。禁止退货整单冲回又按退货额再冲一次，不扩现金退款。

已关联退货的销售更正属于技术整合风险：不变量是原成交快照不改写、退货不重复冲回、可退量不变负、修订链净销售等于有效销售加有效反向事件。提案由ROOT统一设计关联修订事务，先加载全部相关有效退货，校验数量和差量，原子调整相关账项；不允许只更正销售而忽略已退数量。未完成这种关联更正路径时应明确受控失败并保留现状，不假装成功，也不额外新增用户必答问题。

数量限定算例：原售2箱×100=200，已退1箱产生反向100，原净100；现将销售数量更正为1箱，旧销售冲回200、正确销售记100，既有退货反向100保留，最终净0，累计已退1箱与正确销售1箱匹配。更正后销售数量若少于已退1箱则拒绝，版本、销售和退货原状不变。此例仅验证数量更正，不预设已退后价格更正的重新计价、退货额重分配规则；后者仍由ROOT细化关联事务合同。

## 7 错误归属与交接

| 候选错误 | 责任口/处理 | 不得采取的捷径 |
| --- | --- | --- |
| AUTH_NOT_ACTIVE / NOT_OWNER | A04云授权，A02业务校验 | 客户端按钮隐藏当权限控制 |
| MASTER_OR_UNIT_INVALID | A02主档 | 跨SKU借单位/缺包装猜瓶数 |
| PRICE_VERSION_CHANGED / ORDER_VERSION_CHANGED | A02；A03提示重新核对 | 静默覆盖新价或已修订单 |
| IDEMPOTENCY_INPUT_CHANGED | A02/ROOT合同 | 同键换内容当成功 |
| ZERO_NOT_EXPLICIT / PRICE_MISSING | A02；A03区分0与空 | 缺价填0、零价写常规价 |
| DOCUMENT_NOT_PERSISTED | A06生成/存储，A02不完成计销 | 预览/下载触发当正式存储 |
| RETURN_SOURCE_INVALID / RETURN_OVER_LIMIT | A02核验原行快照和累计额度 | 使用现价、跨原行累计或并发超退 |

A01负责事件运输/恢复，A02业务权威，A03交互，A04身份，A05只消费有效纠错，A06单据/打印，A07独立验证。台账现有PRICE-01/CORRECTION-01仍残留“步长等未选”描述，07已解决部分应由ROOT更新，本口不改台账。候选未获ROOT冻结不记合同通过。
