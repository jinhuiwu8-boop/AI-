# W1-A01 normalized收单实现回交

日期：2026-10-31；合同：contract-w1.1；开发基线：w1-local-v0.1。责任口A01，ROOT更新进度。此次是可运行本地代码，不是企业微信、Jetson或生产云验收。

## 文件与接口

- `src/intake/index.mjs`：导出createIntakeService({store,now})，提供receive、sealDue、listBatches、listJobs。
- `test/intake/intake.test.mjs`：真实共享store与node:sqlite测试，无业务数据、无网络。
- 本文为回交；未修改共享文件、根package、schema、台账、锁文件或旧源码。

来源必须active===true；匹配来源id（兼容sourceId）。消息幂等范围为sourceId＋conversationId＋messageId，规范输入相同返回原结果且duplicate=true，不续时；同ID不同规范内容DomainError MESSAGE_CONFLICT/409。未授权SOURCE_FORBIDDEN/403，事务回滚。

客户提示开启批次；首次有效product启动60秒，每条新product续时；纯客户提示不生成任务。切客户封已有商品批次，未归属和封单后迟到产品存UNASSIGNED，不猜归属。封单与任务写入同一共享store事务，唯一任务WAITING_EDGE，截止时间和版本存state。list方法深拷贝；无价格、确认、销售或实际打印调用。

媒体只接受受控元数据id及可选mimeType、sizeBytes、sha256、relativePath；IMAGE/VOICE缺引用拒绝，绝对/父级路径及任意URL字段拒绝。这里未读取媒体文件、核验存在或下载；元数据接收绝不标记媒体下载成功。官方微信媒体上限仍未核验，代码输入防御不代表官方上限。

## normalized调用样例

```js
service.receive({sourceId:'local-source-1',conversationId:'demo',messageId:'m1',
  type:'TEXT',kind:'customer',text:'好运店',customerHint:'好运店',media:[]});
service.receive({sourceId:'local-source-1',conversationId:'demo',messageId:'m2',
  type:'TEXT',kind:'product',text:'示例饮料2箱',media:[]});
// 可控时钟到最后一条product后60秒，或由ROOT的本地定时器调用：
service.sealDue();
```

receive返回`{messageId,batchId,status:'BATCHED'|'UNASSIGNED',duplicate}`；sealDue返回`{sealedCount,sealed:[{batchId,jobId}]}`。批次含id、sourceId、conversationId、customerHint、status、version、productCount、messageIds、deadline、jobId；任务含冻结消息ID、批次版本及WAITING_EDGE，不伪造识别结果。

## 实际验证

运行环境：用户工作区，Node v24.19指定运行时。命令：

```powershell
& 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --check '.\src\intake\index.mjs'
& 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --test '.\test\intake\intake.test.mjs'
```

语法检查exit0；最终测试exit0，tests=6、pass=6、fail=0、skip=0。测试覆盖：

1. 首产品起算、续时、重复不续时、截止前1毫秒及精确边界、封批重复不多建任务。
2. 新客户切批、纯客户不建空任务、无归属与截止时迟到。
3. 来源/会话隔离、同ID异内容冲突回滚、停用/未知来源拒绝、返回深拷贝。
4. TEXT/IMAGE/VOICE归批、缺引用及危险路径/任意URL字段拒绝。
5. 真实SQLite关闭重开后从持久截止封批，重放消息/再次重启仍单任务。
6. 两个SQLite连接交错处理同消息与sealDue，读取一致且单任务。该项是交错事务验证，未冒称多进程压力测试。

所有临时SQLite位于系统临时测试目录，用后关闭清理；未打开旧业务库。测试确认orders和salesEvents保持空，normalized层不计销。
