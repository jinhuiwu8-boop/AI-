## 交互与错误处理

- 手机底部导航和桌面窄侧栏；页面文字由 DOM `textContent`/文本节点输出，无动态 `innerHTML`。
- 所有写操作由 bootstrap 获取 CSRF 令牌，使用 JSON 同源请求。前端没有老板权限开关，云端鉴权仍是最终依据。
- 编辑客户、SKU、单位、数量、价格、抵扣、抹零、备注和 0 元确认会重置整单核对勾。异步取价同时使用客户/SKU/单位标识、每行请求代次及价格编辑代次：旧请求不能覆盖新请求，请求期间的人工价与明确 0 价优先，只更新最新报价来源和版本。
- 提交期间禁用写按钮，重复点击由共享 busy 状态拦截。网络未知时在会话存储保留同一 `operationId` 和完整 payload，阻止新写操作，提供“查询 / 重试原请求”；刷新页面后继续使用该请求。服务端明确拒绝才释放此请求。
- 服务端已经返回成功而汇总刷新失败时，仍认定原写操作成功，保留返回的正式单据，不误导用户再次开单。
- 报价或订单版本冲突后要求重新核对。普通取价行刷新有效价，人工改价及历史更正保持人工编辑值并重新读取价版本。
- 金额显示和核对小计只为预估，服务端负责正式金额、到角、计销、更正冲回和防超退。前端乘积、合计和到角使用 BigInt 中间值；超出安全整数范围时显示“待服务端校验”，不显示失真的金额。

## 本次验证

- Node.js `--check web/app.mjs` 通过。
- 本地开发服务 `http://127.0.0.1:3210` 的 bootstrap 已读取，返回 `LOCAL_DEVELOPMENT`、2 个合成客户及 2 个合成 SKU。
- 同一 cookie 会话读取 `GET /api/progress`，字段与页面消费合同一致；没有 cookie 的请求收到 `SESSION_REQUIRED`，页面请求使用 `credentials: same-origin`。
- 静态检查无联网字体/图片/脚本依赖，无 `eval` 或动态 `innerHTML`。
- 定点修复后以 Node 独立抽取并执行实际报价保护函数，断言人工价优先、同身份旧请求失效、最新请求生效、明确 0 元保留以及身份变化；安全整数边界和乘积溢出断言通过。源码断言无需求折算百分比和内联宽度。
- 最终静态复核后，客户价格编辑器的 `loadPrice` 也加入编辑器对象引用、单调请求代次及价格编辑代次保护；快速 A→B→A 的旧请求不能覆盖新 A，只有当前请求能够更新报价、解锁或提示错误，期间手改值优先。Node 语法检查再次通过；此后本轮 UI 冻结。
- ROOT 已尝试 Computer 浏览器实测，但插件无法可靠识别当前 Windows 浏览器 URL，因此停止本轮 UI 操作；尚未完成视觉与点击验收，无截图验收证据。本回交不代签独立 UI 验收或手机现场验收。

## 仍未声称完成

此版本是可操作的本地业务网页，不是华为 APK 完成证明。真实企业微信媒体上传、Jetson OCR/ASR、模型训练、锁屏提醒、原生相册和系统认证仍等待相应专业口接入。图片下载明确称“浏览器下载”，未称华为原生相册保存成功。打印只登记真实待设备请求，没有伪造佳能 iP110 已连接、已出纸或已验纸。

原销售含抵扣/抹零时，退货反向分配规则尚未确定，页面明确提示当前受控拒绝；更正已退货单的受限情形由服务端拒绝并显示真实原因。未上传 Git，未操作生产服务、真实手机或打印机。
